## 技术债务

### 已知的代码问题
1. **retrieval.py 复杂度高**：多种检索策略（hybrid、two-stage、supplement）混在一起，难以维护
2. **prompt.py 脆弱**：小的改动可能导致 LLM 行为剧变（如全部拒答）
3. **evidence.py 未充分使用**：建好了基础设施但没有在最终流程中发挥作用

### 潜在的架构改进
1. **检索策略路由**：根据 query 类型自动选择最优的检索策略
2. **Prompt 模板系统**：将 prompt 拆分成可组合的模块，降低改动风险
3. **评测驱动开发**：建立自动化评测流程，每次改动都有量化指标
