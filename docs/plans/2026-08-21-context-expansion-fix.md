# 下一步计划 (2026-08-21)

## 本次完成（context expansion bug 修复）

**根因**：`pipeline.py:357-374` 的 context expansion 用 `before + c.text + after` 拼接后**整体覆盖 `c.text`**。当 chunk 在数据库里的物理位置相邻 chunk 跨 section 边界（如"合并资产负债表"在"合并利润表"前面），拼接后的文本开头是邻居章节内容，原始 chunk 自身的关键数字被推到拼接文本中后段，触发 LLM 截断时看不到核心数据。

**实证**（Q17「三一重工2023-2025年营业收入」）：
- 数据库中三个 chunk 的真实 text 均含完整数字（73,221,725 / 77,773,391 / 89,231,023）
- 但 diagnostics `text_preview` 显示 2024 chunk 是"合并资产负债表"开头（商誉、长期待摊费用、应付账款等）——是邻居 chunk 的内容
- `get_neighbor_chunks(anchors, expand_n=2)` 实测：2024 chunk `_529c3649c7` 的 before（3554 字符）= 合并资产负债表，after（1810 字符）= 合并利润表尾巴，c.text 自身（1825 字符）= 合并利润表头部
- 拼接后 c.text 长度 7189 字符，前 800 字符（preview 截断）全是资产负债表内容，**完全没有营业收入 77,773,391 这个数字**
- LLM 只能凭训练记忆答对 2023（732.22 亿广为人知），拒答 2024/2025「年报未披露」

**修复**：`app/core/pipeline.py` 禁用 context expansion（删除 `get_neighbor_chunks` 调用块），保留 chunk 原始 text 直接给 LLM。注释里说明禁用原因：邻居极可能跨 section，污染 > 帮助。

**验证**：
- 重跑 Q17：topk_chars 从 46160 降到 10074（去除拼接污染），LLM 看到完整三年数据
