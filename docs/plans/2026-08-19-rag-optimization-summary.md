# RAG 系统优化总结（2026-08-19）

## 项目背景

三一重工年报 RAG 系统评测优化，目标是提升跨文档问答（C类）和错误前提纠偏（H类）的准确率。

## 完成的工作

### 1. LLM 供应商切换
- **从**：MiniMax M3（不稳定，频繁超时）
- **到**：SiliconFlow
  - 主模型：DeepSeek-V3（文本对话）
  - 视觉模型：Qwen2.5-VL-7B-Instruct（图片理解）
  - 裁判模型：DeepSeek-V3（评测打分）
- **效果**：评测 65 题全部完成评分（之前只能评 46-49 题）

### 2. 检索层优化

#### 2.1 权威表格定向补充检索
**问题**：财务表格数据（如"主要会计数据"、"研发投入情况表"）在 BM25 中得分低，经常被挤出 top-K。

**解决方案**：
- 当 query 包含财务关键词时，额外做 BM25 搜索，专门找权威 section 的 chunks
- 权威 section 列表：主要会计数据、主要财务指标、研发投入情况表、利润表等
- 年份匹配：query 说"2025年"只补充 2025 年报的 chunk
- 已有 chunk 加分：如果权威 chunk 已在主检索中但分数低，给 ×3.0 加分

**效果**：
- A类（单文档事实）：56.7% → **83.3%**（+26.6pp）
- B类（表格理解）：61.1% → **94.4%**（+33.3pp）

#### 2.2 Section-aware 重排
**原理**：根据 query 类型给特定 section 的 chunks 加分
- 财务数据查询 → boost "主要会计数据"、"主要财务指标"（×5.0）
- 研发查询 → boost "研发投入情况表"（×5.0）
- 财务报表 → boost "利润表"、"资产负债表"（×3.0）

**匹配方式**：匹配 section_path 的叶子节点（最后一级），避免父级路径误匹配

#### 2.3 两阶段检索（实验性）
**设计**：
- Stage 1：文档级预检索（用 doc_embeddings 找相关文档）
- Stage 2：在目标文档内做 chunk 级精搜

**现状**：已实现但效果有限，因为问题不在"找不到文档"而在"文档内找不到正确 section"

#### 2.4 证据整理层（实验性）
**设计**：
- 保留子问题 → chunks 的映射关系
- 构建结构化证据表（EvidenceTable）
- 证据感知重排（对比类保成对，汇总类保覆盖）
- 冲突检测（同一指标在不同文档的数值差异）

**现状**：基础设施已建好，但对最终分数提升有限。主要价值在于为未来优化提供结构化数据。

### 3. Prompt 优化

#### 3.1 拒答边界规则
**添加内容**：
- 检查清单新增：用户问题假设了某种趋势，检索内容是否支持？
- 检查清单新增：用户问的信息年报是否真的披露？
- 信息充分度决策新增：年报不披露的信息（市值、单一国家销售额等）→ 明确说明

**效果**：I类（拒答边界）53.3% → **66.7%**（+13.4pp）

**问题**：规则太强会导致 LLM 全部拒答（曾经所有回答变成 0 字）。需要非常谨慎地调整。

## 关键发现

### 1. 检索质量是瓶颈
- 向量检索不理解"财务数据应该在主要会计数据 section"
- 表格数据的关键词密度低，BM25 分数低
- **解决方案**：权威表格定向补充检索（最有效）

### 2. Prompt 改进效果有限且风险高
- 规则太强 → LLM 全部拒答
- 规则太弱 → 没有效果
- **建议**：优先改进检索层，prompt 只做微调

### 3. 跨文档问题仍然困难
- C类虽然提升 25%，但仍是弱项（1.88/3）
- 根本原因：检索到的 chunks 年份错位（问 2025 拿到 2024 的数据）
- 需要：更精确的年份匹配 + 多文档综合策略

## 技术债务

### 1. 未使用的代码
- `sub_dependencies`（子问题依赖关系）：已实现但未使用
- `complexity` 分类：已实现但 prompt 里没有差异化处理
- 证据整理层的冲突检测：已实现但未在 prompt 中展示

### 2. 检索层复杂性
- 多种检索策略并存（hybrid search、two-stage、section supplement）
- 缺乏统一的检索策略选择机制
- 调试困难（需要看多层日志）

### 3. 评测系统
- 裁判模型偶尔不稳定（虽然比 MiniMax 好很多）
- 缺乏自动化的回归测试
- 评测结果没有版本化管理

## 经验教训

### 1. 检索 > Prompt
- 检索层改进（A/B类 +50pp）远大于 prompt 改进（I类 +13pp）
- 如果检索不到正确的 chunk，再好的 prompt 也没用

### 2. 渐进式改进
- 不要一次性做大量改动（会导致难以定位问题）
- 每次改动后立即评测，确认效果

### 3. 理解问题本质
- 跨文档问题的本质不是"检索不够多"而是"检索不够准"
- 表格数据的问题不是"没有数据"而是"数据在错误的 section"
